# M0-06 — Persist every run; `runs` list/show; a shared projection

**Milestone:** M0 · **Size:** M · **Depends on:** M0-03 · **Status:** ⬜ Not started
**Written against:** commit `b9496e7` (2026-08-08)

## Summary

A run leaves nothing behind unless `--events FILE` was passed. There is no history, no way to
look at yesterday's failure, and nothing for a UI to show. The archived design
(`docs/archive/design-2026-05.md` §1) called for an event log as the authoritative record;
T01 shipped the stream but not the log.

This task makes the log real with almost no new machinery: every run's NDJSON stream is
written to a per-run directory under the user's data dir, a `meta.json` summary is written at
the end, and a **projection** module folds a stream of events into a run summary. That same
projection is what the console, the future UI (M3), and replay (M6-03) will use, so "any view
of a run is a fold over its events" becomes true in code.

## In scope

- `TinyCI.Runs`: locations, `list/2`, `load/2`, `projection/2`, `prune/2`.
- `TinyCI.Runs.Projection`: fold events (as decoded NDJSON maps) into a `%Projection{}`.
- `TinyCI.Runs.Recorder`: an `EventSink` that writes `events.ndjson` and, on close, `meta.json`.
- `TinyCI.Events.PipelineStarted` gains `branch`, `commit`, `base_ref`, and `root` fields;
  schema version 2 → 3.
- Executor: recorder attached by default; `record: false` disables it.
- `mix tiny_ci.runs` (list / show / prune) and `--no-record` on `mix tiny_ci.run`.
- `docs/runs.md`; `docs/events.md` updated for schema 3.

## Out of scope

- A database of any kind. Directories and NDJSON are the store; M3 reads them.
- Replay UI (M6-03). This task only has to make the data available and foldable.
- Server-side retention policies beyond a simple `keep: N` prune (M2-07 sets the default).

## Design

### Layout

```
<runs_base>/<project_id>/<run_id>/events.ndjson   # the recording; appended during the run
<runs_base>/<project_id>/<run_id>/meta.json       # written once, atomically, at close
```

`runs_base` = `Application.get_env(:tiny_ci, :runs_base_dir)` ||
`Path.join(System.get_env("XDG_DATA_HOME") || Path.join(System.user_home!(), ".local/share"), "tiny_ci/runs")`.
`project_id` = `TinyCI.Artifacts.project_id(root)`. `run_id` = `ctx.run_id` (already
generated by `Artifacts.generate_run_id/1`; it sorts chronologically as a string).

### `TinyCI.Events.PipelineStarted` (schema 3)

Add `branch`, `commit`, `base_ref`, `root` (all strings or nil). The executor fills them from
the context. Bump `@schema_version` to 3; the NDJSON `run_started` line carries them. This is
the only place the run's git identity is recorded, so the listing can show it without a
separate write.

### `TinyCI.Runs.Projection`

Events are represented as **decoded NDJSON maps** (string keys, `"type"`, `"seq"`, `"ts"`).
Live events are converted with `NDJSON.encode_line/2 |> Jason.decode!/1` before being applied.
One representation, one fold, no struct/map dual paths.

```elixir
defmodule TinyCI.Runs.Projection do
  defstruct run_id: nil, pipeline: nil, status: :running, schema_version: nil,
            branch: nil, commit: nil, base_ref: nil, root: nil,
            started_at: nil, finished_at: nil, duration_ms: nil,
            stages: [],            # ordered by first appearance; see below
            divergent?: false, breakpoints: [], last_seq: 0

  @type stage :: %{name: String.t(), status: :running | :passed | :failed | :skipped | :aborted,
                   duration_ms: non_neg_integer() | nil, reason: String.t() | nil,
                   steps: [step()], matrix_runs: [matrix_run()]}
  @type step :: %{name: String.t(), status: atom(), duration_ms: non_neg_integer() | nil,
                  attempts: pos_integer(), cache: :hit | :miss | nil, output: [String.t()]}

  @spec new() :: t()
  @spec apply(t(), map()) :: t()
  @spec fold(Enumerable.t()) :: t()          # Enum.reduce(events, new(), &apply(&2, &1))
  @spec to_json(t()) :: map()                # superset of Results.to_json/2's shape
end
```

Event → effect table (the agent implements exactly this):

| type | effect |
|---|---|
| `run_started` | run_id, pipeline, schema_version, branch, commit, base_ref, root, started_at |
| `run_finished` | status (`passed`/`failed`/`aborted`), finished_at, duration_ms |
| `stage_started` | append stage `%{status: :running}` if absent |
| `stage_skipped` | stage status `:skipped`, reason |
| `stage_finished` | stage status, duration_ms |
| `step_started` | append step `%{status: :running, attempts: 1}` under its stage |
| `step_skipped` | step status `:skipped` |
| `step_output` | append `line` to the step's `output` |
| `step_retrying` | step `attempts = attempt` |
| `step_finished` | step status, duration_ms |
| `matrix_run_started` / `matrix_run_finished` | append/update `matrix_runs` entry keyed by `combination` |
| `cache_lookup` | step `cache` |
| `hook_started` / `hook_finished` | ignore in this task (record under `hooks` if trivial) |
| `breakpoint_hit` / `breakpoint_resumed` | append to `breakpoints` |
| `run_diverged` | `divergent?: true` |
| anything else | ignore (forward compatibility) |

`last_seq` is the highest `seq` seen. A projection whose `status` is still `:running` after the
stream ends is reported as `:interrupted` by `Runs.list/2` (the process died before
`run_finished`).

### `TinyCI.Runs.Recorder` (an `EventSink`)

- `init(root: root, run_id: id)`: `File.mkdir_p!` the run dir; open `events.ndjson` for write;
  state holds the device and a `Projection`.
- `handle_event(seq, event, state)`: `line = NDJSON.encode_line(seq, event)`; write it; apply
  `Jason.decode!(line)` to the projection.
- `close(state)`: close the device; write `meta.json` = `Projection.to_json/1` to
  `meta.json.tmp` then `File.rename/2`.

The recorder must never fail the run: wrap file operations so an unwritable data dir logs one
warning and disables itself (return state with `disabled?: true`). The dispatcher already
isolates a raising sink, but a disabled recorder is quieter than a stack trace per event.

### `TinyCI.Runs`

```elixir
@spec base_dir() :: String.t()
@spec dir(root :: String.t(), run_id :: String.t()) :: String.t()
@spec list(root :: String.t(), keyword()) :: [Projection.t()]     # newest first; opts: limit (default 20)
@spec load(root, run_id) :: {:ok, Enumerable.t()} | {:error, :not_found}   # File.stream! of decoded maps
@spec projection(root, run_id) :: {:ok, Projection.t()} | {:error, :not_found}
@spec prune(root, keyword()) :: %{removed: non_neg_integer()}       # opts: keep (default 200)
```

`list/2` reads `meta.json` when present and otherwise folds `events.ndjson` (marking
`:interrupted`). `prune/2` deletes the oldest run dirs beyond `keep`.

### Executor

`build_sink_specs/3` appends `{Runs.Recorder, root: ctx.root, run_id: ctx.run_id}` unless
`opts[:record] == false`. Only when `ctx.root` is set (standalone `Executor.execute/4` calls in
tests have no root and must not write to the real data dir — the ephemeral dispatcher path
must **not** add a recorder). `PipelineStarted` is emitted with the new fields.

### Mix tasks

- `mix tiny_ci.runs` — table: `run_id  status  pipeline  branch  commit(7)  duration  started`.
  `--limit N`, `--output json` (list of `Projection.to_json/1`), `--root DIR`.
- `mix tiny_ci.runs show RUN_ID [--output json] [--events]` — the reporter-style tree from
  the projection; `--events` prints the raw NDJSON.
- `mix tiny_ci.runs prune [--keep N]`.
- `mix tiny_ci.run --no-record`.

## Acceptance criteria

- [ ] Every `mix tiny_ci.run` (not `--dry-run`, not `--no-record`) leaves `events.ndjson` and
      `meta.json` under the data dir.
- [ ] `run_started` carries branch, commit, base_ref, root; schema version is 3 and documented.
- [ ] `Projection.fold/1` over a recorded stream reproduces the run's statuses, durations,
      output, matrix runs, attempts, and divergence.
- [ ] A run killed mid-way lists as `interrupted`.
- [ ] `mix tiny_ci.runs`, `runs show`, `runs prune` work and are documented.
- [ ] The recorder never affects the run's exit code.

## Pitfalls

- `Artifacts.generate_run_id/1` includes the branch name; branch names can contain `/`. Check
  how `Artifacts` sanitises it and reuse the same function, or run dirs will nest unexpectedly.
- `File.stream!/1` on the NDJSON keeps the file open lazily; `load/2` callers must consume or
  the handle lingers in tests. Prefer `Enum.to_list/1` in tests.
- Do not put the projection on the context or in the dispatcher state; the recorder owns it.
- `Jason.encode!` of the `PipelineStarted` struct: the new fields must be in the
  `@derive {Jason.Encoder, ...}` list (or whatever mechanism `events.ex` uses per struct).
